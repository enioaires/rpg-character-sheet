```typescript
import { describe, it, expect } from 'vitest'
import { calculateAttributeTotal } from '@/lib/calculations'

describe('calculateAttributeTotal', () => {
  it('sums race, class, and bonus below level 5', () => {
    expect(calculateAttributeTotal({ race: 10, class: 12, bonus: 2 }, 4)).toBe(24)
  })

  it('adds floor(level / 5) at level 5 and above', () => {
    expect(calculateAttributeTotal({ race: 10, class: 12, bonus: 2 }, 10)).toBe(26)
  })
})
```

The `@/` alias must also be configured in the test runner (Vitest needs `vite-tsconfig-paths` or an explicit `resolve.alias`), because `tsconfig.json` defines `paths` but a test runner does not read them by default.

## Mocking

**Framework:** Not installed.

**Recommended approach:**
- Mock the Prisma client at the module boundary in `lib/db/index.ts`. Replace the `db` export rather than the `PrismaClient` class, because the route handlers in `app/api/[[...route]]/characters/index.ts` import `db` directly.
- Mock `fetch` or the Hono client (`lib/api/client.ts`) when testing hooks in `lib/api/queries.ts`. Hooks call `api.characters.$get`, `api.characters[':id'].$put`, and similar methods.
- Mock `sonner` `toast` when testing components that call `toast.success` or `toast.error` (for example `app/characters/page.tsx`).

**What to Mock:**
- Prisma (`@/lib/db`) for API route tests.
- The Hono client (`@/lib/api/client`) for hook tests.
- `next/navigation` (`useRouter`) for page and component tests.
- `sonner` for toast assertions.

**What NOT to Mock:**
- Pure calculation helpers in `lib/calculations/index.ts` and `lib/constants/character.ts`. Test them directly with real inputs.
- Zod schemas in `lib/schemas/`. Validate real payloads through `safeParse`.
- The `cn` helper in `lib/utils.ts`.
